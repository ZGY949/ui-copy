# 说明文字的处理示例

围绕页面中的描述性、解释性文字选择处理方式。以下为设计与实施示例，使用时核对实际任务、能力和授权范围。

## 1. 长句缩成标题或短语

**原说明**

> 在这里，你可以查看和管理自己创建的所有项目。

**呈现**

页面标题“我的项目”，下方直接展示项目列表。已有标题与列表表达对象时，删除重复介绍；无需再放“欢迎使用项目管理功能”。

标题承担对象识别，按钮承担动作。例如“新建项目”“筛选”“排序”；不要将同一段功能介绍改写后分别放在标题、卡片和按钮旁。

## 2. 操作说明转成可操作控件

**原说明**

> 你可以根据项目的状态筛选列表，查看正在进行或已经完成的项目。

**呈现**

在列表附近提供状态筛选：“全部／进行中／已完成”，明确当前选择。

**成立条件与实施**

- 列表状态数据已可用，任务允许页面实现或交互优化时，可实现本地筛选，复用现有数据与组件。
- 切换选项后实际更新列表；检查筛选后的空态，以及清除或切回全部的行为。
- 控件已解释操作时，删除原来的使用说明。必要的筛选条件或当前范围可用短标签显示。
- 只有文字修改授权时，给出筛选区的具体建议；数据能力缺失时说明所需改动，不补造可用功能。

同样的判断适用于搜索框、视图切换、排序入口和编辑动作。每个控件都要对应真实行为，不仅改变外观。

## 3. 空态保留状态与直接动作

**原说明**

> 目前还没有任何项目。你可以点击下面的按钮创建第一个项目，创建之后就可以在这里查看和管理它。

**呈现**

“暂无项目”＋“新建项目”按钮。

任务允许调整页面且已有新建入口时，将按钮接到真实创建流程；用户看到状态与动作即可继续，不再附一段操作教程。

搜索无结果时，给出当前结果及实际可用的调整条件或清除筛选动作。读取失败时呈现失败与恢复方式，不能伪装成“暂无项目”。没有待处理事项的平静状态不必强行提供创建动作。

## 4. 说明回到它对应的位置

| 信息承担的任务 | 更合适的位置与形式 |
|---|---|
| 输入内容是什么 | 字段标签；不只靠会消失的占位符 |
| 输入示例或格式 | 简短占位符或字段附近的提示 |
| 真实的必填、数量或格式限制 | 输入前可见的短提示；错误时就地指出可修正内容 |
| 某个对象当前的情况 | 对象旁的状态标签或结果区 |
| 只有少数人需要的术语解释 | 明确的“说明”入口、展开区或详情层 |
| 点击后有费用、权限或不可撤销后果 | 用户决定前的操作区、确认或必要告知 |

例如，将页面顶部“请在下方输入项目名称……”的介绍移除，直接提供“项目名称”标签；只有实际限制需要提前知道时才添加就地提示。

帮助入口与输入方式匹配：触屏不能只用悬停Tooltip。不能将用户作决定必需的信息藏进帮助入口，或为每个字段增加一张解释卡片。

## 5. 冗长描述提示了入口或流程问题

> 点击右上角图标后，可以打开筛选面板，再选择需要的状态。

先检查入口：图标含义是否清楚，筛选是否足够常用，是否应改成可见“筛选”按钮或直接展开的筛选区。若入口已经清楚，删除多余教程；若需要调整交互，按任务范围实施并验证。

类似地，“长按这里可以排序”不能在删除后仅剩难以发现的手势。使用清楚的排序入口、手柄或适合平台的可发现操作；需要原生手势效果时在目标平台验证。

## 6. 应保留的说明

- 永久删除、费用、权限和数据影响，需要在决定前表达真实后果。
- 输入或业务存在不常见的实际限制时，保留能帮助完成任务的短提示。
- 失败恢复需要具体可执行的信息，不能只剩“出错了”。
- 首次使用或复杂流程确实需要引导时，按步骤给必要信息；不将全套教程持续放在每个常用页面。
- 文章、课程内容、用户填写的正文以及地点、日期、计数等任务数据，按其内容目标处理。

简洁来自文字、位置与交互各负其责。删除后用户更难理解、需要猜测，或操作只是看起来可点，都没有解决原问题。
