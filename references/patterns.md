# 组件与状态

按本次涉及的组件阅读对应小节。以下是判断示例，示例里的功能和数据前提需要在使用的产品中真实成立。

## 1. 标题、入口与按钮

标题与标签回答“是什么”，操作回答“将做什么”。同一操作区的主要动作应容易识别；如果主次不清源于布局，指出这一点，不靠文案擅自改变控件样式。

| 场景与真实行为 | 容易误导的表达 | 建议与依据 |
|---|---|---|
| 打开本机文件选择器，尚未上传 | 上传完成 | 选择文件；只承诺立即发生的动作 |
| 当前步骤已经选好文件，按钮开始上传 | 下一步 | 上传文件；比抽象步骤更可预期 |
| 三步向导的第一步，下一屏任务已写清 | 无须强行更换“下一步” | 可以保留“下一步”，同一向导保持一致 |
| 完成设置仅关闭面板，设置即时生效 | 保存设置 | 完成或关闭；不能虚构额外的保存动作 |
| 导航到历史记录列表 | 处理历史记录 | 历史记录；导航标签可以使用名词 |
| 图标删除列表中的某一文件 | 辅助名称为“垃圾桶” | 删除文件，必要时包含文件名；描述动作而非图形 |

操作文本优先表达动作与对象；当前语境已清楚时，“关闭”“取消”等短词可用。不要求所有标签、导航和按钮统一成同一种句式。

## 2. 表单与校验

标签、占位符和辅助说明承担不同任务。错误要说明怎么修正，而不是只报“输入无效”。格式限制来自实际校验规则，不自行制造限制。

例如，在产品确实要求邮箱用于接收报告时：标签“邮箱”；占位符“例如 name@example.com”；需要说明用途时写“报告会发送到这个邮箱”。不要把用途塞进标签，也不把占位符当永久字段名称。

只有实现确实要求密码至少 12 个字符时，才可将“密码不符合要求”改为“密码至少需要 12 个字符”。如果当前输入还有其他不符项，分别指出或采用产品现有的合并规则。

涉及隐私、权限或费用的必要告知放在用户作出决定前；普通格式示例无需制造确认步骤。

## 3. 空态、加载与成功

| 实际状态 | 可采用的文字 | 下一步条件 |
|---|---|---|
| 首次使用，确实没有文件 | 还没有文件 | 产品支持上传时可给“上传文件”入口 |
| 搜索成功，但没有匹配项 | 没有找到匹配的文件 | 搜索条件可调整时，给出调整入口或简短建议 |
| 有数据，但读取失败 | 文件列表暂时无法读取 | 只有已有重新读取能力时才给“重新读取” |
| 没有需要处理的提醒 | 暂无待处理提醒 | 无需强行给创建提醒的动作 |
| 正在上传，未取得可靠进度 | 正在上传 | 不补造“即将完成”、百分比或剩余时间 |
| 文件已保存到本机，尚未同步 | 已保存到本机，尚未同步 | 同步状态和操作按产品实际能力表达 |
| 服务端确认已同步 | 已同步 | 当前界面已清楚展示结果时，可省略重复轻提示 |

空态不是一律“没有内容”，也不是每次必须带操作。加载不是成功；完成提交也不必然表示发布或对方已收到。

## 4. 错误、恢复与结果未知

优先说明未完成的事，再提供已知影响和可执行的恢复动作。错误尽量出现在相关字段或操作附近，长期有效的信息不只放在转瞬消失的轻提示里。

| 前提 | 候选文案 | 为什么 |
|---|---|---|
| 读取失败，原因未知，支持重新读取 | 文件列表未能读取，请重新读取 | 不把未知原因断言为网络问题 |
| 保存失败，当前输入已证实仍在页面 | 未能保存，已保留本页内容 | 只说已经核对的数据影响，不扩大为所有数据安全 |
| 无权查看文件，产品支持申请访问 | 你还没有查看权限 | 配“申请访问”，不假装文件不存在 |
| 提交超时，服务端结果未知，支持查询记录 | 暂未确认提交结果，请先查看提交记录 | 不写“提交失败，请重新提交”，避免重复操作 |
| 提交超时，查询和安全重试均未证实 | 暂未确认提交结果 | 恢复动作待确认，不自行添加重试或联系支持入口 |

技术信息可以进入实际存在的问题详情、诊断工具或支持流程。受众确实需要错误码时保留它，但同时提供可理解的说明；没有详情入口时，不虚构一个入口。

## 5. 确认、删除与撤销

| 真实行为 | 候选标题／正文／操作 |
|---|---|
| 永久删除文件，无恢复能力 | “删除文件？”／“删除后无法恢复。”／“删除文件”“取消” |
| 仅从当前列表移除，原文件仍保留 | “移除文件？”／需要时说明“原文件仍会保留。”／“移除文件”“取消” |
| 丢弃本次未保存修改，保留此前保存版本 | “放弃本次修改？”／“未保存的修改将丢失。”／“放弃修改”“继续编辑” |
| 已有真实撤销能力 | 结果“已移除文件”配“撤销”；不能仅添加“撤销”文字而没有动作 |

后果因对象不同而变化。不要把“可恢复”“保留原文件”或“不会影响其他人”等示例事实复制到没有验证的业务里。

## 6. 通知、分享与可访问名称

通知与分享往往脱离原界面。写清对象、状态和接收者能采取的动作；时间与数量使用真实数据。

- 在消息确实发送成功时，状态可写“已发送”；没有送达或已读证据时，不能写“对方已收到”或“对方已查看”。
- 分享标题可以描述“本周项目报告”，但只有访问状态已成立时才暗示接收者能直接查看。
- “查看详情”作为独立链接或读屏名称时可能缺少对象；按语境可用“查看报告详情”。
- 纯图标名称应描述实际动作，相关状态也需正确；同时检查可见标签与辅助名称有没有因局部修改而不一致。
